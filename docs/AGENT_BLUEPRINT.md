# 陪伴 Agent 的架构与需求清单

> Nichijou 陪伴 Agent 平台 · 架构与需求草案 v1 · 2026-09-03
> 现状诊断部分基于当前 `main` 分支代码。开源项目评估参考各项目公开文档与 2026 年多份横向对比。

现有代码已经把「世界观、记忆、技能」三件事都占了位，但三处都还是壳：记忆是关键词 `LIKE` 查询，世界观是四个字符串字段全量拼进 prompt，技能是硬编码插件加罐头回复。这份文档给出要补的东西、可验收的需求、目标架构，以及值得直接抄的开源项目。

---

## 01 — 结论先行：三个判断

如果这份文档只有人读三段，读这三段。

### 判断一 · 记忆是护城河，不是功能

陪伴产品唯一无法被大模型升级抹平的资产，是「它记得我」。现在的实现是关键词匹配加正则抽事实，撑不过 50 轮。这一项应当是最高优先级，且必须和评测集一起交付。

### 判断二 · Skill 现在不是能力，是菜单

模型不会自己决定调用任何 skill，用户得手打 `/skills tarot`，结果是写死的文案。要的是「声明式清单 + 模型自主 tool calling + 结果回灌角色口吻」。

### 判断三 · 世界观要能被检索，而不是被拼接

长设定全量进 prompt 必然爆上下文、且稀释人设。世界观应当实体化成可被关键词/向量触发的条目库，并能被同世界观的多个角色共享。

## 02 — 现状诊断：五个「看起来有、实际是壳」的地方

以下每条都来自当前仓库代码，不是推测。

| 编号 | 领域 | 问题 | 代码位置 |
|---|---|---|---|
| G-1 | 记忆 | 单表 `CharacterMemory`，检索是 `content contains 关键词`，写入靠正则命中「我喜欢／好き／生日」就存一条。没有向量、没有去重、没有冲突消解、没有时间线、没有遗忘。命中不到就退化成「取最近 8 条」。远程 `MEMOS_API_URL` 那条路径是个没有实现的接口契约。 | `src/lib/ai/memos-plugin.ts` → `extractMemorableFacts()` / `queryMemosLocal()` |
| G-2 | 世界观 | `identity` / `worldRules` / `brandVoice` / `boundaries` 四个字符串字段，每轮全量拼进 system prompt。没有条目化、没有触发条件、没有优先级，多个角色无法共享同一个世界，设定一长就必然挤掉对话历史。 | `src/lib/agent/prompt.ts` → `buildPersonaSystemPrompt()` |
| G-3 | 技能 | `registerSkill()` 注册的是硬编码 TS 插件，带一个 `cannedReply` 罐头文案。调用靠用户输入 `/skills xxx` 正则匹配。没有参数 schema、没有执行沙箱、模型完全不参与决策，创作者也无法新增。加一个技能 = 改主仓库 + 发版。 | `src/modules/agent/skills/registry.ts` · `src/lib/chat-skill-command.ts` |
| G-4 | 编排 | 固定四步直线 pipeline，没有 agent loop，工具结果无法回灌重新生成，没有生成后校验。记忆写入同步阻塞在请求路径上，直接抬高每轮延迟。回复整段返回，没有流式。 | `src/lib/ai/pipeline.ts` → `runChatPipeline()` |
| G-5 | 关系状态 | 亲密度是一个 0–100 的整数，关系摘要是 `[新, 旧].join(" / ").slice(0, 280)` —— 字符串拼接后硬截断。轮次一多，摘要会退化成一串互相矛盾的句子碎片，而它正被注入 prompt 当作「关系事实」。 | `src/lib/agent/relationship.ts` → `recordBondInteraction()` |

## 03 — 需求清单：给 agent 开发提什么

每条需求带可验收标准。编号用于排期和回归追踪，不要改。

### PER — 人设与世界观

#### PER-1 · 人设分五层，各层生命周期不同

- **Core Identity**：名字、物种、根本设定。不可变，改了就是另一个角色。
- **Persona**：性格、语气、口癖、边界。可版本化，带 diff 与回滚（`PersonaRevision` 已有骨架）。
- **World Canon**：世界规则、地点、事件、其他角色。独立实体，可被多个角色共享。
- **Scene State**：当前时间、地点、在做什么、情绪。会话级，可被剧情推进。
- **Relationship**：user × character，见 PER-5。

**验收**：同世界观的两个角色能引用同一条世界设定；改一次世界设定，两个角色的回答同时更新，且各自口吻不变。

#### PER-2 · 世界观条目化，按触发检索注入

新增 `World` + `LoreEntry` 实体。每条 lore 带：`keys[]`（关键词触发）、`secondaryKeys[]`、`priority`、`constant`（是否常驻）、`scanDepth`（回看几轮）、`enabled`。每轮扫描最近 N 轮对话，命中则按优先级注入，未命中不进 prompt。

这套数据模型直接照抄 SillyTavern 的 World Info —— 它是被百万级用户验证过的事实标准，没必要重新发明。

**验收**：一份 3000 字的世界设定，实际每轮注入 ≤ 600 token，相关条目召回率 ≥ 90%。

#### PER-3 · system_prompt 与 post_history 分离

持久契约（我是谁、世界规则、绝对边界）放 system prompt；最后一轮的行为纠偏（别 OOC、别替用户说话、控制长度）放在历史之后的一段独立指令。模型对「最后看到的指令」服从度显著更高，这是长对话不崩人设的关键工程手段。

**验收**：100 条越界诱导测试集上，人设崩坏（OOC / 自称 AI / 违反 boundaries）率 < 3%。

#### PER-4 · 创作者侧要有「世界」这个一等对象

Studio 里能建世界、写 lore 条目、把角色挂到世界上。lore 条目支持 AI 辅助生成与冲突检查（新条目与已有条目矛盾时提示）。

**验收**：非技术创作者能在 10 分钟内建出一个含 20 条 lore 的世界并让角色正确引用。

#### PER-5 · 关系状态结构化，替换字符串截断

把 `bond.summary` 换成结构化对象：称呼方式、共同经历事件列表（带时间）、未兑现的约定、已知禁忌、当前情绪基调。摘要由 LLM 周期性重写而非拼接，且有 token 上限。

**验收**：200 轮对话后，关系摘要无自相矛盾条目，长度稳定不增长。

### MEM — 记忆

#### MEM-1 · 记忆分层，不是一张表

- **Working**：当前会话窗口 + 滚动摘要
- **Episodic**：事件（时间、地点、参与者、情绪、原文引用）
- **Semantic**：稳定事实（姓名、生日、职业、偏好、禁忌）
- **Relational**：见 PER-5
- **Procedural**：角色学到的互动习惯（「他不喜欢被追问工作」）

**验收**：每类记忆有独立的写入策略、TTL 与检索权重，可分别关闭做消融测试。

#### MEM-2 · 写入是 LLM 抽取 + 冲突消解，不是正则

抽取出候选事实后，先与已有记忆做相似检索，再决定 `ADD / UPDATE / INVALIDATE / NOOP`。旧事实不物理删除，标记失效并保留 `valid_from` / `valid_to` 双时间戳。

验证场景：用户上个月说喜欢猫，本周说养了狗。角色既要知道「现在养狗」，也要能在合适时候提起「你以前说喜欢猫的」。

**验收**：时序变更类问题（什么变了 / 什么时候变的）准确率 ≥ 60%；重复事实入库率 < 5%。

#### MEM-3 · 检索走混合召回 + 重排

向量（pgvector，你们已经在 Postgres 上，别引第二个存储）+ BM25 关键词 + 实体/时间过滤，融合后重排取 top-k。k 由上下文预算决定，不是写死的 8。

**验收**：检索 P95 < 150ms；自建中文/日文长程测试集上事实召回 ≥ 85%。

#### MEM-4 · 写入异步化，读取才在关键路径上

当前 `mandatoryMemosStore` 在返回回复前同步落库，白白抬高每轮延迟。改成回复流式返回后投递到队列，由 worker 抽取入库。

**验收**：TTFT < 800ms；记忆写入失败不影响回复成功。

#### MEM-5 · 遗忘与固化

低重要度且长期未命中的记忆按时间衰减并归档。空闲时段跑批：episodic → semantic 固化、冗余合并、关系摘要重写。这类「离线整理」是记忆质量随时间上升而不是下降的前提。

**验收**：单个 user × character 的活跃记忆条目数收敛，不随对话轮次线性增长。

#### MEM-6 · 记忆对用户可见、可改、可删

条目级的查看 / 编辑 / 删除，而不是现在的「一键清空」。这既是体验（用户纠正「我说的是三月不是五月」），也是合规要求（GDPR 数据主体权利，已有 `src/lib/privacy/erase.ts`）。

**验收**：用户删除一条记忆后，下一轮对话中该事实不再出现在注入上下文里。

#### MEM-7 · 承诺追踪

角色说过的、指向未来的话（「明天问你面试结果」「周末一起看那部电影」）单独入库为待兑现项，到期进入下一轮的注入上下文。这是陪伴感最强的单点功能，成本极低。

**验收**：承诺到期后首轮对话主动提起率 ≥ 80%，误提（已兑现还问）率 < 10%。

### SKL — 技能

#### SKL-1 · Skill 是声明式清单，不是 TS 代码

一个 skill 由一份 manifest 定义：`id`、给模型看的描述、输入 JSON Schema、执行方式（`prompt` / `http` / `mcp`）、权限、计费、内容分级、触发方式。存库，不进代码仓库。

**验收**：新增一个技能不改主仓库代码、不发版。

#### SKL-2 · 三条调用路径都要支持

- **模型自主**：tool calling。角色发现用户在纠结感情问题，自己决定起一卦。
- **用户显式**：`/skills` 或点按钮（现有路径，保留）。
- **系统触发**：生日、久未联系、承诺到期。

**验收**：技能误触发率 < 5%（不该调时调了）；该调未调率 < 15%。

#### SKL-3 · 技能结果必须回灌角色再润色

塔罗抽出的牌面是数据，说出口的话必须是这个角色的口吻、并结合她记得的这个用户的处境。现在的 `cannedReply` 直出罐头文案，是角色感最大的破绽。

**验收**：盲测中，技能回复与普通对话回复的「像不像同一个角色」评分差 < 0.5 分（5 分制）。

#### SKL-4 · 创作者能自建技能

第一档：Studio 填表就能出一个 prompt 型 skill（占卜、哄睡、剧情本、角色小剧场）。第二档：挂自己的 HTTP endpoint。第三档：接 MCP server。后两档必须有沙箱、超时、配额、审核队列。

**验收**：创作者 5 分钟内发布一个 prompt 型技能；外部 endpoint 超时不会拖垮对话（降级为角色自然圆场）。

#### SKL-5 · 外部技能走 MCP，不要自造协议

Model Context Protocol 已经是工具接入的事实标准，生态里现成的 server 可以直接用。自定义协议的唯一结果是把自己隔离在生态之外。

**验收**：能接入任意一个第三方 MCP server 并被角色正确调用。

#### SKL-6 · 技能描述渐进式加载

技能一多，光是工具定义就能吃掉几千 token。做法：只有简短描述常驻上下文，模型决定使用后才加载完整定义与用法。这是 Anthropic Agent Skills 的核心设计，直接照搬。

**验收**：挂载 50 个技能时，常驻工具定义 token < 800。

### ORC — 编排

#### ORC-1 · 固定四步换成有限步 agent loop

`retrieve → plan → (tool calls)* → generate → post-check → persist`，最大步数与最大成本双重封顶。

**验收**：单轮最大 LLM 调用数与花费有硬上限，超限降级而不是无限循环。

#### ORC-2 · 生成后校验 —— 体感的分水岭

三个轻量 checker 并行跑在草稿回复上：人设一致性、边界合规、记忆矛盾。任一不过就带着失败原因重生成一次（只重生成一次，避免成本失控）。

**验收**：重生成触发率 5–15%（太低说明 checker 没用，太高说明主 prompt 有问题）；重生成后通过率 ≥ 90%。

#### ORC-3 · 上下文预算器

system prompt 不是拼接出来的，是分配出来的。见第 05 节。

**验收**：任意角色、任意世界观规模下，注入总 token 不超过档位上限。

#### ORC-4 · 全链路 trace

每轮记录：注入了哪些 lore / memory 条目、调了哪些 skill、走了哪个模型档、各阶段耗时、花了多少钱。没有这个既没法调优也没法定价。已有 `AiUsageLog`，扩展它。

**验收**：能对任意一次「回复很奇怪」的投诉，10 秒内还原当时的完整注入上下文。

#### ORC-5 · 流式优先

当前整段返回。改成 SSE 流式，post-check 在流式结束后跑；若不通过，UI 层做「正在想…」的重写过渡。

**验收**：TTFT < 800ms（P95）。

### EVL — 评测

#### EVL-1 · 四套测试集，和功能同批交付

人设一致性、长程记忆召回、越界安全、技能触发准确率，各 100 条以上，覆盖中/日/繁三语。**这一条不是「有余力再做」。** 陪伴产品没有评测集，调 prompt 就是玄学，谁也说不清昨天的改动是变好还是变坏。

**验收**：测试集入库、可版本化、CI 里能跑。

#### EVL-2 · LLM-as-judge + 人工抽检

自动评分跑全量，人工每周抽检 30 条校准 judge 与人的一致性。judge 的 prompt 本身也要版本化。

**验收**：judge 与人工评分一致率 ≥ 80%。

#### EVL-3 · 回归门禁

任何 prompt、模型路由、检索策略的改动都要跑全量回归，关键指标下降超过阈值则阻断合并。

**验收**：回归跑完 < 20 分钟，单次成本可接受（用低档模型做 judge）。

标注 `[增强]` 为已有并需增强，`[新增]` 为新增。

|---|---|
| **接入层** Interface | `[增强]` Chat（改流式） · `[增强]` Voice Call · `[增强]` Feed/动态 · `[新增]` 主动消息 |
| **编排层** Orchestrator | `[新增]` retrieve → `[新增]` plan → `[新增]` tool calls* → `[增强]` generate → `[新增]` post-check → `[增强]` persist |
| **上下文装配** Context Builder | `[新增]` 预算分配器 · `[增强]` Core Persona · `[新增]` World Lore 检索 · `[新增]` Memory 检索 · `[增强]` Bond · `[新增]` Scene State · `[增强]` History 摘要 |

| **记忆服务** Memory | `[新增]` 写：抽取 → 消解冲突 → embed → 索引（异步队列） · `[新增]` 读：向量 + BM25 + 时间过滤 → rerank · `[新增]` 离线：固化 / 衰减 / 摘要重写 |

| **治理** Governance | `[增强]` moderation · `[增强]` age gate · `[增强]` content rating · `[增强]` boundaries · `[新增]` 记忆可删除 · `[新增]` skill 审核 |

> **一个务实的边界**：不建议整体引入 Letta 这类「接管 agent 全部状态」的框架 —— 角色状态和计费、订阅、创作者分成深度耦合，交出去代价太大。建议自建编排层，只把记忆服务做成可替换的接口（现有 `memos-plugin.ts` 已经是这个形状），这样以后换 mem0 / 自建 / 商业方案都只改一个文件。

## 05 — 上下文预算：system prompt 是分配出来的

下面是免费档（8K 上下文）的一个建议分配。付费档按比例放大，但比例结构不变。超预算时按 priority 裁剪，而不是无脑截断。

| 组成 | 预算 | 方式 |
|---|---|---|
| Core Persona | ~450 tok | 固定 |
| World Lore | ~600 tok | 检索 top-k |
| Memory | ~550 tok | 检索 top-k |
| Bond | ~250 tok | 结构化 |
| Scene | ~180 tok | 会话级 |
| History + 回复余量 | 剩余 | 滚动摘要 |

裁剪优先级从高到低：`constant lore` → `高分 memory` → `Bond` → `低分 lore` → `History 尾部`。

`Core Persona` 与 `boundaries` 永不裁剪 —— 宁可少记一件事，也不能让角色崩了或越界。

## 06 — 开源参考：值得抄的项目

按「拿来直接用 / 抄设计 / 观望」分类。不建议一次引入多个框架。

### 世界观与角色扮演 —— 这块最值得抄

| 项目 | 它解决了什么 | 对我们意味着什么 | 结论 |
|---|---|---|---|

| [Generative Agents](https://github.com/joonspk-research/generative_agents) · Stanford | 记忆流 + 重要性打分 + reflection（从琐碎事件里归纳出高层认知）+ 基于记忆的主动行为。 | MEM-5 的固化机制和主动性设计的原始出处，论文和代码都值得读一遍。 | 抄思路 |

### 记忆

| 项目 | 它解决了什么 | 对我们意味着什么 | 结论 |
|---|---|---|---|
| [mem0](https://github.com/mem0ai/mem0) · Apache-2.0 | 最轻的 drop-in 记忆层：抽取事实、跨 user/session/agent 分域、检索时融合语义与关键词信号。Token 占用极省。 | `memos-plugin.ts` 接口形状已经和它几乎一样，替换成本最低。**建议作为第一版落地目标。** | **直接用** |
| [Graphiti / Zep](https://github.com/getzep/graphiti) · Apache-2.0 | 时序知识图谱，双时间戳，事实变更时旧事实失效而非删除。在 LongMemEval 上明显领先扁平向量方案。 | MEM-2 的冲突消解机制照它抄。**但注意代价**：图构建成本高，且有「写入后要等后台处理完才检索得到」的延迟问题 —— 对实时聊天是硬伤。 | 抄机制，慎全量引入 |
| [Letta（前 MemGPT）](https://github.com/letta-ai/letta) · Apache-2.0 | 把记忆当作 agent 状态本身：memory blocks、agent 自己编辑自己的记忆、空闲时段的离线整理。 | 「记忆是状态不是检索」这个思想值得吸收（MEM-5）。但它要接管整个 agent 生命周期，和计费/分成耦合冲突。 | 抄思路 |
| [cognee](https://github.com/topoteretes/cognee) · Apache-2.0 | 把记忆当 ETL 管线：ingest → 构图 → 检索，各环节可替换。 | 如果自建记忆服务，它的管线分层是不错的骨架参考。 | 观望 |

## 07 — 落地顺序：四个阶段

周期按 2–3 人的 agent 小组估。评测集放在第一阶段，不是最后。

| 阶段 | 周期 | 内容 | 覆盖需求 |
|---|---|---|---|
| **P0** | 3–4 周 | **记忆重做 + 评测底座** —— pgvector 上线，LLM 抽取替换正则，冲突消解与双时间戳，写入异步化，同时把四套评测集建起来。评测集先行，后面所有改动才有参照系。 | `MEM-1` `MEM-2` `MEM-3` `MEM-4` `EVL-1` `EVL-2` |
| **P0** | 2–3 周 | **Skill manifest + tool calling** —— 技能定义入库，接上模型自主调用，结果回灌角色润色。可以和记忆并行做，两条线交集小。 | `SKL-1` `SKL-2` `SKL-3` `ORC-1` |
| **P1** | 3 周 | **世界观实体化 + 上下文预算器** —— World / LoreEntry 建模，触发式检索注入，预算分配器接管 prompt 装配，system 与 post-history 分离。 | `PER-1` `PER-2` `PER-3` `ORC-3` |
| **P1** | 2 周 | **生成后校验 + 流式 + trace** —— 三个 checker 上线并接回归门禁，回复改流式，全链路 trace 打通。这一阶段结束时体感会有明显跃升。 | `ORC-2` `ORC-4` `ORC-5` `EVL-3` `PER-5` |
| **P2** | 3–4 周 | **创作者自建技能 + MCP + 记忆管理界面** —— Studio 里的技能编辑器、外部 endpoint 沙箱、MCP 接入、用户侧记忆的条目级查看与删除。 | `SKL-4` `SKL-5` `SKL-6` `MEM-6` `PER-4` |
| **P3** | 持续 | **主动性与离线固化** —— 承诺追踪、空闲时段的记忆固化与衰减、基于记忆钩子的主动消息。这是留存曲线的长期杠杆，但要放在前面都稳了之后。 | `MEM-5` `MEM-7` |

> **关于优先级的一个提醒**：LoRA 和声纹克隆已经做了不少工作，但它们提升的是「像不像」，记忆和技能提升的是「值不值得每天回来」。留存曲线更吃后者。建议这几个季度把算力预算的重心从形象训练挪到记忆基础设施上。
