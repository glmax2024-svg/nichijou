# 训练接口对接需要确认的问题

对接目标：画师在 Studio 上传参考图 → 平台调用 `POST /api/train/jobs` → 轮询进度 → 训练完成后角色可直接用于生图。

已经确认的部分（不用再答）：鉴权用 ANIMA key，`Authorization: Bearer` 和 `X-API-Key` 都可以；ZETTA key 无效；训练参数固定（2000 步 / rank 32 / alpha 32 / lr 2e-5 / 1024 / bf16 / seed 42 / 打标阈值 0.35）；训练产物会出现在 `GET /api/image/loras` 里（已看到 `satoru_gojo`）。

---

## 1. 响应体字段（最要紧）

OpenAPI 里这些接口的响应都是空 schema（`"schema": {}`），我们没法照着写代码。**麻烦各发一份真实响应的 JSON**：

| 接口 | 需要的示例 |
|---|---|
| `POST /jobs` → 202 | 提交成功时的完整响应 |
| `GET /jobs/{id}` | 排队中 / 训练中 / 成功 / 失败，四种状态各一份 |
| `GET /jobs/{id}/checkpoint` | 成功时的响应 |
| `GET /jobs/{id}/captions` | 自动标注的结果 |
| `GET /jobs/{id}/previews/{angle}` | 返回的是 JSON 还是图片二进制？ |
| `GET /submissions/{request_key}` | 用 idempotency-key 反查的结果 |
| `POST /jobs/{id}/cancel` → 202 | 取消后的响应 |
| 各类错误 | 图片太少、格式不对、重名、配额超限时的响应 |

配套问题：

1. **`status` 有哪些取值？**（我们要映射到内部的 QUEUED / TRAINING / READY / FAILED）
2. **有没有进度字段？** 是百分比还是「当前步数 / 2000」？前端要显示进度条。
3. **失败时错误原因放在哪个字段？** 我们需要把可读的原因展示给画师。
4. **排队信息**：能拿到「前面还有几个任务」或预计开始时间吗？

## 2. 训练完成后如何用于生图

5. 训练完成后是**自动注册**到生图服务的吗？还是需要人工放文件？
6. 从「状态变成完成」到「`/api/image/loras` 里能查到」大概要多久？
7. `/generate` 的 `lora` 参数是不是就等于提交时的 `character`？
8. **同一个 `character` 再训练一次会怎样？** 覆盖旧的、报错、还是生成新版本？我们需要支持画师重训。
9. `/loras` 里的 `textEncoder`（`satoru_gojo` 是 true，`laiwanting` 是 false）是什么含义，生图时要不要跟着改参数？
10. `appearanceVariants`（如 `sunglasses` / `blindfold`）是怎么产生的？是不是只是建议加进 prompt 的标签？
11. **有删除 LoRA 的接口吗？** 画师删角色、或用户要求删除数据时需要。

## 3. `character` 命名

12. 允许的字符和长度上限？（文档写的是英文、数字、下划线）
13. **重名怎么处理？** 我们平台上不同画师可能取同样的名字，是不是需要我们自己加前缀（比如 `nichijou_<characterId>`）？
14. 触发词就是 `character` 本身，那 `/loras` 里返回的 `recommendedPromptPrefix`（如 `laiwanting, one girl, red hair`）是从标注里自动统计出来的吗？

## 4. 图片要求

15. 单张大小上限、**总请求体上限**（100 张大图可能有几百 MB）
16. 最小/最大分辨率，长宽比有没有要求，需不需要我们先裁成正方形
17. 支持透明背景 PNG 吗？
18. 建议张数（5–100 之间，多少张效果最好）
19. 如果混进了别的角色或者质量差的图，会被自动过滤还是直接影响效果？

## 5. 任务与配额

20. 能同时跑几个训练？超过会排队还是直接拒绝？
21. 单次训练大概多久？（用于我们提示画师等待时间）
22. 每天 / 每个 key 有上限吗？
23. **有没有完成回调（webhook）？** 现在只能轮询，有回调的话体验和成本都会好很多。如果有，麻烦说明签名方式。
24. 任务记录、checkpoint、预览图、日志各保留多久？会自动清理吗？

## 6. 稳定性（实测遇到的问题）

25. **HTTPS 偶发握手失败**：连续请求时多次出现 `curl exit 35`（SSL connect error），重试才成功，`/api/image` 和 `/api/train` 都出现过。上传上百张图时这个影响很大，麻烦查一下 Caddy 或隧道那边。
26. 上传大 multipart 时，Caddy 和应用侧的 body 上限、超时分别是多少？
27. 网络中断导致上传失败时，用同一个 `idempotency-key` 重试是**续传**还是**从头重传**？`/submissions/{request_key}` 是不是就是用来判断「上次是否已经提交成功」的？

## 7. 其他

28. 训练用的图片你们那边会保留吗？保留多久？（涉及我们对画师的隐私说明）
29. 有没有测试环境或者小规模快速训练的模式？我们联调时不想每次都占用 GPU 跑 2000 步。
